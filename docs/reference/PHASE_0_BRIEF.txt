3. DEMO VS REAL — IMPORTANT ARCHITECTURE DECISION
======================================================================

Build ONE production-quality trading system, not a “toy demo bot” followed by a later rewrite.

Strategy logic, market-state logic, risk calculations, order intents, reconciliation, journaling and monitoring should be common across environments.

Environment/account mode must be explicit and typed, e.g.:

    RESEARCH
    BACKTEST
    PAPER
    DEMO
    SHADOW
    LIVE_LIMITED
    LIVE

Exness Demo and Exness Real should use the same Exness execution adapter semantics wherever the broker/API/MT5 behavior permits.

The account/profile/credentials determine WHICH Exness account is connected.

However, merely replacing a demo account number with a real account number MUST NOT silently enable live trading.

Real trading requires additional independent gates such as:
- environment = LIVE or LIVE_LIMITED;
- explicitly enabled venue/instrument policy;
- explicit LiveTradingPermit / release artifact;
- successful live-readiness qualification;
- step-up owner authentication for activation;
- hard startup refusal if gates disagree.

Therefore:
the system is REAL-CAPABLE from architecture day one,
but REAL-MONEY execution remains technically impossible until future gates are deliberately satisfied.

No Phase 0 task may connect or place orders on demo or real accounts.
